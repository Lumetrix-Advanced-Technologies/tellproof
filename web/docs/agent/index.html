The evidence agent

The agent runs next to your AI product. It receives spans from the Plumbline SDK (or any OpenTelemetry exporter), drops all message content, and sends Plumbline one signed batch of aggregates per hour. It is open source, and --dry-run shows exactly what it would send.

Try it locally

Local mode needs no account, no server and no token. The agent signs each hourly batch with a key of its own and keeps it in its data directory; nothing is sent anywhere.

pip install plumbline-agent && plumbline-agent run --local
npx plumbline-agent run --local
docker run -d --name plumbline-agent -p 127.0.0.1:4318:4318 -p 127.0.0.1:4319:4319 \
  -v plumbline-agent:/data ghcr.io/lumetrix-advanced-technologies/plumbline-agent:latest run --local

Add the SDK to your app (below), make a model call, and about a minute later open the dashboard at http://127.0.0.1:4319: calls and tokens per model and region, guardrail coverage and personal-data redaction over time, tool use, a timeline of changes, anomalies and evaluations, and the evidence chain. The agent serves it on loopback only and it loads nothing from elsewhere. Set PLUMBLINE_DASHBOARD_LISTEN (or dashboard_listen) to move it, or to off. The same figures in a terminal:

plumbline-agent report
plumbline-agent report --json --since 2026-10-01

report checks every batch's signature against agent.pub and the chain from the first batch, then sums the calls per model and region, guardrail decisions, personal-data redaction, agent activity, prompt and model changes and anomalies. It exits 1 if a batch was edited or is missing. Keep a copy of agent.pub elsewhere: the log proves it has not changed relative to that key.

For packs evaluated against Plumbline's evidence objectives and signed by an independent issuer, which a reviewer can verify, request early access to the hosted service. Connecting starts a new agent with its own data directory; the local log stays local.

Connect to Plumbline

  1. In the Plumbline app, open your AI system's Setup and sources page and choose Create enrolment token. The page shows the command below with the token and server filled in. The token works once, for 24 hours.
  2. Run the agent with it, then add one line to your app.
docker run -d --name plumbline-agent --restart unless-stopped -p 127.0.0.1:4318:4318 \
  -v plumbline-agent:/data -e PLUMBLINE_SERVER=https://<server> \
  ghcr.io/lumetrix-advanced-technologies/plumbline-agent:latest connect <token>

connect enrols the agent if its data directory is not enrolled yet, then runs. Running the same command again, for example after a restart, does not enrol again. About a minute after your app's first model call, the system page lists the agent and its first batch.

Install

Container

The image ghcr.io/lumetrix-advanced-technologies/plumbline-agent is a static binary on a distroless base, for linux/amd64 and linux/arm64, running as a non-root user. Keep the /data volume (see the data directory).

Binary

Release binaries for Linux, macOS and Windows on amd64 and arm64 are on the open-source repository's Releases page. Check a download before you run it:

sha256sum --ignore-missing -c SHA256SUMS
gh attestation verify plumbline-agent-linux-amd64 --repo lumetrix-advanced-technologies/plumbline
PLUMBLINE_SERVER=https://<server> ./plumbline-agent-linux-amd64 connect <token>

Use a plumbline-agent-bedrock-* binary if you need Amazon Bedrock usage from CloudWatch.

From source

go install github.com/lumetrix-advanced-technologies/plumbline/cmd/agent@latest

pip or npm

pip install plumbline-agent or npm install -g plumbline-agent (or npx plumbline-agent) install the same static binary as the release for your platform. Nothing is downloaded at install time and nothing runs on install.

Instrument your app

Install the SDK (pip install plumbline-sdk or npm install plumbline-sdk) and add one line at start-up:

import plumbline; plumbline.init()                              # Python 3.10+
import * as plumbline from 'plumbline-sdk'; plumbline.init();   // Node.js 18+

The SDK instruments the OpenAI, Anthropic and Bedrock client libraries that are installed. It records one span per model call (provider, model, region, token counts, operation, timing and error status) and never reads prompts, completions, arguments or return values. It has no dependencies, and it never blocks or breaks your app: if the agent is down, spans are dropped and counted.

Environment variableDefaultMeaning
PLUMBLINE_AGENT_URLhttp://127.0.0.1:4318Where the agent listens.
PLUMBLINE_SERVICEOTEL_SERVICE_NAMEThe service name on every span.

Serving your own models? There is no client library to patch: wrap each inference request in your serving layer with plumbline.llm_call("your-company", model, region=...) (Node.js: plumbline.llmCall({provider, model, region}, fn)) and report the tokens with c.usage(input, output).

Without the SDK, point an OTLP/HTTP JSON exporter at http://127.0.0.1:4318/v1/traces and set the plumbline.* attributes yourself, as listed in spec/semconv-map.json. Do not use both for the same calls, or they are counted twice.

See what would be sent

Dry run prints every batch the agent would send, with its payload decoded, and sends, queues and stores nothing. Replay feeds an OTLP JSON export through the same pipeline and exits:

plumbline-agent run --config agent.json --dry-run
plumbline-agent run --config agent.json --dry-run --replay export.jsonl

A batch holds counts and short names only: tokens and calls per provider, model and region, counts of spans with personal data and how many were redacted, guardrail and evaluation results, agent activity counts, which models and prompt versions were live, and one Merkle root over the hour's traces. The full format is spec/batch.schema.json.

Configuration

connect needs no file. For anything more, write a JSON file and pass --config agent.json. These environment variables override it:

Environment variableConfig keyDefault
PLUMBLINE_SERVERservernone (required)
PLUMBLINE_DATA_DIRdata_dir./.plumbline-agent (/data in the container)
PLUMBLINE_OTLP_LISTENotlp_listen127.0.0.1:4318
PLUMBLINE_DASHBOARD_LISTENdashboard_listen127.0.0.1:4319 in local mode; off turns it off
PLUMBLINE_OTLP_ALLOW_REMOTE=1otlp_allow_remoteoff: only loopback addresses may be used
PLUMBLINE_ENROL_TOKENThe token for plumbline-agent enrol when --token is not given.
PLUMBLINE_SALT_SECRETsalt_secret_env names the variableWith connect, a random secret kept in the data directory.

A complete file, with every source off:

{
  "server": "https://<server>",
  "data_dir": "./.plumbline-agent",
  "otlp_listen": "127.0.0.1:4318",
  "langfuse": { "enabled": false, "base_url": "https://cloud.langfuse.com",
                "public_key_env": "LANGFUSE_PUBLIC_KEY", "secret_key_env": "LANGFUSE_SECRET_KEY", "eval_scores": [] },
  "usage": {
    "openai":    { "enabled": false, "admin_key_env": "OPENAI_ADMIN_KEY", "project_ids": [] },
    "anthropic": { "enabled": false, "admin_key_env": "ANTHROPIC_ADMIN_KEY", "workspace_ids": [] },
    "bedrock":   { "enabled": false, "region": "ap-southeast-2" }
  },
  "salt_secret_env": "PLUMBLINE_SALT_SECRET",
  "salt_secret_file": "",
  "aggregation": { "grace_minutes": 5, "first_batch_seconds": 60,
                   "anomaly": { "min_calls": 20, "error_rate": 0.05, "guardrail_block_rate": 0.03 } }
}

Secrets are never written in the file. The file names the environment variable that holds each one (*_env), or a file with mode 0600 for the salt secret.

  • aggregation.grace_minutes: how long after the hour a window stays open for late spans. Later spans are counted in the next window as late.
  • aggregation.first_batch_seconds: after a start, the open hour is sent once this long after the first spans, so a new agent shows up at once. The rest of the hour follows when it closes.
  • aggregation.anomaly: an hour with at least min_calls calls and an error or guardrail-block rate above these is reported as an anomaly window.

More evidence sources

Each source is read-only and off until you turn it on.

  • Langfuse (langfuse): pulls traces from Langfuse with your project keys, dropping content the same way. eval_scores maps a Langfuse score to an evaluation suite: {"name": "faithfulness", "suite": "rag-eval", "pass_at_least": 0.8}.
  • OpenAI and Anthropic usage (usage.openai, usage.anthropic): polls the providers' usage APIs with an admin key, so a pack can compare traced tokens with billed tokens (the coverage objective). Limit it to the projects or workspaces of this system.
  • Amazon Bedrock usage (usage.bedrock): reads Bedrock's CloudWatch metrics in region with the default AWS credential chain. Needs a -bedrock build.

The data directory

Keep it, and back it up. It holds:

  • the agent's Ed25519 private key (mode 0600), which signs every batch; losing it means enrolling a new agent;
  • the queue of batches not yet accepted by the server, fsynced before they are acknowledged and retried with backoff of up to 15 minutes;
  • each window's commitment leaves and, with connect, salt.secret. Together they let you later disclose one trace to a reviewer and prove it was counted, without revealing any other.

Networking

  • Inbound: only the span receiver, on 127.0.0.1:4318 by default. It has no authentication. Inside the container it listens on all interfaces, and the documented command publishes it on the host's loopback only. If your app runs on other hosts (for example other pods), allow remote addresses and restrict who can reach the port with a network policy or firewall.
  • Outbound: the Plumbline server you configure, over HTTPS. If you turn them on, also the Langfuse API and the providers' usage APIs.

Troubleshooting

  • No agent on the system page: check the agent's log for an enrolment error. An expired or used token needs a new one from the app. The same connect line works again once the data directory is enrolled.
  • Agent listed, no batches: check that your app reaches PLUMBLINE_AGENT_URL, and run --dry-run to see what the agent is building.
  • Counts doubled: the SDK and another OpenTelemetry exporter are both sending the same calls to the agent. Use one.
  • Exit status: 0 ok, 1 runtime error, 2 usage or configuration error. plumbline-agent version prints the version.
